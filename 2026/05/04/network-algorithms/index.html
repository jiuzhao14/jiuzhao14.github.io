网络路由与交换系统中的核心算法

一、最短路径路由算法

1.1 Dijkstra 算法（OSPF / IS-IS 的核心引擎）

1.1.1 算法原理

Dijkstra 算法采用贪心策略：每次都选择当前距离源点最近的未处理节点，确定其最短路径后，用它去松弛（relax）其邻居节点。算法维护两个集合：

  • $S$：已确定最短路径的节点集合（已访问）
  • $U$：尚未确定最短路径的节点集合（未访问）

1.1.2 松弛操作的核心不等式

对于边 $(u, v)$，松弛操作的逻辑是：经过 $u$ 到达 $v$ 是否比当前已知的到达 $v$ 的路径更短？

推导思路：假设源点到 $u$ 的最短距离 $d[u]$ 已经确定（因为 $u$ 刚从 $U$ 中选出）。那么从源点经过 $u$ 再到 $v$ 的总距离为 $d[u] + w(u,v)$。如果这个值小于当前记录的 $d[v]$，则更新 $d[v]$，并将 $u$ 设为 $v$ 的前驱节点。

1.1.4 为什么贪心策略成立（正确性直觉）

核心观察：对于边权非负的图，当前 $d$ 值最小的未处理节点，其 $d$ 值一定就是最终的最短距离。

证明（反证）：假设 $v$ 是当前 $d$ 最小的未处理节点，但存在一条更短路径到 $v$。那条路径必然经过某个未处理的中间节点 $x$。由于边权非负，$d[x] \leq$（经过 $x$ 到 $v$ 的距离）< 当前记录的 $d[v]$。但这与 $v$ 是当前 $d$ 最小的未处理节点矛盾。因此 $d[v]$ 已经是最短路径。

1.2 Bellman-Ford 算法（距离向量路由 / RIP / BGP 基础）

1.2.1 算法原理

与 Dijkstra 不同，Bellman-Ford 采用动态规划思想：在第 $k$ 轮迭代中，找到从源点出发经过最多 $k$ 条边到达各节点的最短路径。由于任何不含负环的最短路径最多包含 $|V|-1$ 条边，故需要进行 $|V|-1$ 轮迭代。

1.2.2 距离向量更新公式推导

每个节点 $x$ 维护一个距离向量（DV），记录 $x$ 到所有目的地 $y$ 的估计最短距离。核心思想是：$x$ 到 $y$ 的最短距离 = $x$ 到某个邻居 $v$ 的直接链路代价 + 该邻居 $v$ 到 $y$ 的最短距离，取所有邻居中的最小值：

这就是 Bellman 方程。当网络拓扑变化或收到邻居更新的 DV 时，节点重新计算上述最小值。若发现更优，则更新自己的 DV 并通知邻居。

1.2.4 计数到无穷（Count-to-Infinity）问题演示

考虑三节点线性拓扑：$A—B—C$，链路代价均为 1。

正常状态，B 的 DV：到 C 为 1（直连）。

故障发生：链路 B-C 断开。B 检测到链路故障，但此时 B 收到 A 发来的 DV，其中 A 声称到 C 的距离为 2（即 A→B→C，A 还不知道 B-C 断了）。

B 收到 A 的 DV 后重新计算：

B 错误地认为可以通过 A 到达 C，距离为 3。B 更新 DV 并通告给 A。

A 收到 B 的更新后：

然后 A 通告给 B，B 再次计算得 $1+4=5$… 如此循环，每轮交换增加 2，直趋无穷。

缓解方法：

  • 水平分割（Split Horizon）：B 不会将通过 A 学到的到 C 的路由再通告回 A
  • 毒性反转（Poison Reverse）：B 主动向 A 通告到 C 的距离为 $\infty$（因为该路由的下一跳就是 A）
  • 触发更新（Triggered Update）：拓扑变化时立即发送更新，不等周期计时器
  • Hold-down 计时器：收到路由不可达信息后，在一段时间内不接受更差的路由

1.2.5 为什么需要 $|V|-1$ 轮迭代

定理：在不含负环的图中，任意两点间的最短路径最多包含 $|V|-1$ 条边（简单路径不重复节点）。因此第 $|V|$ 轮迭代若仍有松弛，说明存在负环。对于网络路由（边权为正），通常远早于 $|V|-1$ 轮即收敛。

1.3 Floyd-Warshall 算法（全源最短路径）

1.3.1 动态规划思想

定义子问题 $d_{ij}^{(k)}$：只允许使用节点集合 $\{1, 2, …, k\}$ 作为中间节点时，从 $i$ 到 $j$ 的最短路径长度。

对于节点 $k$，只有两种可能：

  1. 不经过 $k$：$d_{ij}^{(k)} = d_{ij}^{(k-1)}$
  2. 经过 $k$：$d_{ij}^{(k)} = d_{ik}^{(k-1)} + d_{kj}^{(k-1)}$（即 $i \rightarrow k \rightarrow j$）

取两者最小值：

边界条件：$d_{ij}^{(0)} = w(i,j)$（直接边的权重，无边则为 $\infty$），对角线 $d_{ii}^{(0)} = 0$。

1.3.3 路径重构

算法执行时维护前驱矩阵 $pred$。当 $d_{ij}^{(k-1)}$ 被 $d_{ik}^{(k-1)} + d_{kj}^{(k-1)}$ 更新时，说明新路径经过 $k$，$pred[i][j] = pred[k][j]$。最终通过递归回溯即可重建完整路径。

二、拥塞控制算法

2.1 TCP Reno — AIMD 加性增/乘性减

2.1.1 AIMD 收敛性推导

两个流共享一条瓶颈链路（容量 $C$），各自的窗口为 $w_1$ 和 $w_2$。加性增阶段：$w_i(t+1) = w_i(t) + a$（$a$ 常设为 1 MSS/RTT）。乘性减阶段：检测到丢包时 $w_i \leftarrow (1-\beta)w_i$（$\beta=0.5$）。

在二维状态空间中的演化：

当 $w_1 + w_2 > BDP = C \cdot RTT$ 时发生丢包。超平面 $w_1 + w_2 = BDP$ 为拥塞边界。

收敛证明（Chiu-Jain 矢量分析）：

定义不均衡程度 $\Delta = |w_1 - w_2|$。

  • 加性增：$\Delta$ 不变（两个窗口同步增加相同量）
  • 乘性减：$\Delta’ = |(1-\beta)w_1 - (1-\beta)w_2| = (1-\beta)\Delta < \Delta$

因此每次拥塞事件后，窗口差异按因子 $(1-\beta)$ 缩小，趋向公平。

2.3 BBR — 基于瓶颈带宽与传播延迟的拥塞控制

2.3.1 问题本质

传统丢包驱动的拥塞控制将丢包作为拥塞信号，但在浅缓冲区（shallow buffer）网络中，丢包发生在队列满之后，此时延迟已经很大。BBR 转而直接估计两个物理约束：

  1. 瓶颈带宽 $BtlBW$：路径上最慢链路的数据传输速率上限
  2. 传播 RTT $RTprop$：路径上无排队时的最小往返时间

核心洞察：当 inflight 数据量恰好等于 $BtlBW \times RTprop$（即 BDP）时，链路利用率 100% 且无排队延迟。这个点称为最优操作点。

2.3.2 Kleinrock 最优操作点理论

  • 带宽受限区（inflight > BDP）：吞吐率饱和 = BtlBW；RTT = RTprop + 队列延迟（随 inflight 线性增长）

两个区域的分界点 $inflight = BDP$ 即 Kleinrock 最优操作点。

四、交换调度算法

4.1 iSLIP — 输入排队交换机的迭代轮询匹配

4.1.1 背景：输入排队与 HOL 阻塞

当输入端口使用单一 FIFO 队列时，若队头数据包的目标输出端口被占用，它后面的数据包即使目标端口空闲也无法被发送——这就是 HOL（Head-of-Line）阻塞，吞吐率上限约 58.6%（均匀流量下）。解决方案是每个输入端口为每个输出端口维护独立的虚拟输出队列（VOQ）。

iSLIP 调度器负责在每个信元时隙将输入端口与输出端口进行匹配，使尽可能多的 VOQ 得到服务。

4.1.4 收敛性分析

定理：iSLIP 的匹配大小随迭代轮数单调增加，且 $\log_2 N + 1$ 轮迭代后收敛。

实际中，$N=16$ 时约 5 轮、$N=64$ 时约 7 轮即可收敛。典型的硬件实现中定时进行 2-3 轮迭代已足够（可达到最大匹配的 90%+ 吞吐率）。

4.3 DWRR — 赤字加权轮询

4.3.1 WRR 的问题与 DWRR 的解决

WRR（Weighted Round Robin）简单按权重给每条流发送固定数量的数据包。但若数据包大小变化（互联网的典型情况），实际分配的带宽可能与权重严重偏离。

示例： 流 A 权重 1，流 B 权重 1（应各得 50% 带宽）。流 A 的数据包均为 1500B，流 B 的数据包均为 64B。WRR 每轮各发 1 个数据包，则流 A 获得 $1500/(1500+64) \approx 95.9\%$ 的带宽——完全失衡。

DWRR 的解决：每轮给每条流分配字节配额（quantum）而非数据包配额。

4.3.2 算法步骤

初始化： 每条流分配一个 quantum $Q_i$（与权重成正比），赤字计数器 $DC_i = 0$。

每轮轮询流 $i$ 时：

  1. $DC_i \leftarrow DC_i + Q_i$（本轮可用配额）
  2. 循环：若 $DC_i \geq \text{size(head_packet)}$，则出队该包，$DC_i \leftarrow DC_i - \text{size(head_packet)}$；否则跳出循环
  3. 本轮结束后 $DC_i$ 保留至下一轮（”赤字”含义）

5.1 ECMP 的哈希函数

5.1.1 设计目标

  • 流保持（Flow Affinity）：同一五元组的流始终映射到同一路径，避免数据包乱序
  • 均衡分布：大量流的情况下，各路径承载的流量接近均匀
  • 弹性：路径增减时，受影响的流尽量少

5.1.2 CRC32 哈希与五元组

5.1.3 流量分布分析——卡方检验直觉

假设 $N=4$ 条路径，$M=1000$ 条流。每条流独立且均匀落到任一路径（理想情况）。

每路径期望流数 $E = M/N = 250$。实际分布的标准差 $\sigma \approx \sqrt{M \cdot \frac{1}{N} \cdot (1-\frac{1}{N})} = \sqrt{1000 \times 0.25 \times 0.75} \approx 13.7$。

变异系数 $CV = \sigma / E \approx 5.5\%$——对于 1000 条流来说分布相当均匀。但若仅有 20 条大象流，分布可能极不均衡。

5.1.4 WCMP 的概率映射

当路径带宽不均匀时（如路径 0=40Gbps, 路径 1=10Gbps），应分配权重 $W_0=4, W_1=1$。

WCMP 实现方式之一是哈希阈值表：将 $[0, hash_max]$ 区间按权重比例划分。例如用 16 位哈希（0-65535）：

  • 路径 0：$[0, 52428]$（占比 80%）
  • 路径 1：$[52429, 65535]$（占比 20%）

5.2 一致性哈希在 ECMP 中的应用

5.2.1 传统取模哈希的成员变更问题

$N=4$ 条路径，哈希 mod 4 分配。当一条路径故障，$N$ 变为 3。几乎所有流的 $hash \bmod 3$ 都与其原始的 $hash \bmod 4$ 不同——全部流都需重新分配，所有 TCP 连接中断。

5.2.2 一致性哈希的解决

将哈希值映射到一个环（hash ring，范围 $[0, 2^{32}-1]$），路径节点也通过哈希映射到环上。流被分配给环上顺时针方向的第一个路径节点。

节点故障迁移量分析：

$N$ 条路径均匀分布在环上，每条路径承担 $1/N$ 的哈希空间。当一条路径故障时，其上的流仅需迁移到下一跳邻居——迁移量 = $1/N$。对比取模哈希的几乎全部迁移（$(N-1)/N$），一致性哈希仅迁移 $1/N$。

虚拟节点（Virtual Node）：在实际部署中，每条物理路径被映射为环上的多个虚拟节点（如 100-200 个），使分布更均匀且支持差异化权重。

6.1.4 压缩优化：Patricia Trie (LC-Trie)

单分支路径合并为一个 skip 节点，存储跳过位数 + 分支点值。将 32 深度的二叉 Trie 压缩至 5-7 次内存访问（IPv4）。IPv6 则需深度优化（如 Tree Bitmap 算法）。

6.2 DIR-24-8 算法

6.2.1 设计原理

IPv4 地址 32 位，大部分实用前缀长度 ≤ 24（含 $/0$ 至 $/24$ 的 25 种可能）。少数前缀长度 25-32。这一观察导致自然的拆分：

  • $TBL24$：大小为 $2^{24} = 16,777,216$ 个条目（16M entries）。每个条目 2 字节（下一跳索引或指向 TBLlong 的指针）。内存占用约 32MB。
  • $TBLlong$：仅需为长度 > 24 的前缀创建。最多 $2^8 = 256$ 条目每前缀。

6.2.2 路由插入过程示例

前缀 192.168.1.0/24 → 下一跳 NH1：

$m=24 \leq 24$。取前 24 位 = 192.168.1 对应的索引范围 $[192.168.1.0, 192.168.1.255]$，这 256 个 $TBL24$ 条目都填入 NH1。

前缀 192.168.1.128/25 → 下一跳 NH2：

$m=25 > 24$。取前 24 位，在 $TBL24$ 中对应 192.168.1 的位置存放一个指向 $TBLlong$ 的指针。在 $TBLlong$ 中，建立 256 条目的表，其中前 128 个条目（索引 0-127）指向 $TBL24$ 中原有的 NH1（/24 的覆盖），后 128 个条目（索引 128-255）填充 NH2（/25 覆盖其范围）。

6.2.3 查找过程示例

查找 IP 192.168.1.100：

  1. 取前 24 位 = 192.168.1，索引 $TBL24$
  2. $TBL24[索引]$ 的最低位（或标志位）指示是否为直接下一跳。若为直接 —— 直接返回 NH1
  3. 完成（1 次内存访问）

查找 IP 192.168.1.200（匹配 /25 前缀）：

  1. 取前 24 位 = 192.168.1，索引 $TBL24$ 获得 $TBLlong$ 指针
  2. 取后 8 位 = 200（若 /25 则关注高位是否 ≥128）
  3. $TBLlong[200]$ 返回 NH2（或 NH1，取决于具体实现）

2 次内存访问。最坏情况始终 2 次内存访问。

七、多播路由与树构建算法

7.1 PIM-SM 的 RPF 与共享树

7.1.1 RPF 检查的推导

组播转发的核心要求是避免路由环路和数据包复制爆炸。RPF（Reverse Path Forwarding）的原理简明而有力：

只从通向源的”正确”接口接收数据包。

具体地，对于源地址 $S$ 发来的多播数据包 $pkt$，接收接口 $in_iface$：

$RPF_interface(S)$ 由单播路由表决定：它是对目的 IP $S$ 执行正常单播查找后得到的出接口。换言之，多播数据包只能从”如果我要发单播给 S，就会用这个接口”的接口进入。

7.1.2 RPF 检查的图示示例

RPF 有效地将组播分发限制在一棵逻辑广播树上（以源为根的最短路径树）。

7.1.3 PIM-SM 共享树（RPT）构建

稀疏模式中，接收者加入以 Rendezvous Point (RP) 为根的共享树：

  1. 最后一跳路由器向 RP 方向（单播路由确定的下一跳）发送 PIM Join 消息
  2. 沿途路由器创建 $(*, G)$ 转发状态，Join 逐跳向上传播到 RP
  3. 形成以 RP 为根、接收者为叶子的单向共享树

源端：源的第一跳路由器将多播数据包封装在单播 PIM Register 消息中发给 RP。RP 解封装后沿共享树转发。可选地，RP 或最后一跳路由器可触发向源的最短路径树切换（SPT switchover），以减少 RP 负载。

7.2 Steiner 树与 KMB 近似算法

7.2.1 形式化定义

输入：无向图 $G=(V,E)$，边代价 $c: E \to \mathbb{R}^+$，终端节点集合 $T \subseteq V$。

输出：连通子图 $G_S \subseteq G$ 包含所有 $T$ 中节点，使得 $\sum_{e \in G_S} c(e)$ 最小。

这是 NP-Hard 问题。即使所有边代价为 1（Steiner 树变为最小斯坦纳树）也是 NP-Hard。

7.2.2 KMB 算法（Kou-Markowsky-Berman）步骤

步骤 1 — 构建完全距离图 $G_D$：

对每对终端节点 $(t_i, t_j)$，在图 $G$ 中计算最短路径距离 $d(t_i, t_j)$。$G_D$ 为以 $T$ 为节点集合的完全图，边权为 $d(t_i, t_j)$。

步骤 2 — 计算 $G_D$ 的最小生成树 MST：

使用 Prim 或 Kruskal 算法，得最小生成树 $T_D$。

步骤 3 — 展开为原图子图：

将 $T_D$ 中的每条边替换为原图中对应的最短路径。得到子图 $G_K$。

步骤 4 — 剪枝去环：

在 $G_K$ 上计算以任意终端为根的 MST，删除所有非终端叶子节点。剩余的便是 Steiner 树近似解。

7.2.3 数值示例

原图 $G$（边上的数字为代价）：

$T = \{t_1, t_2, t_3\}$，其他节点为 Steiner 节点。

步骤 1 — 计算终端间最短路径：

  • $d(t_1, t_2) = \min(2+3=5, 4+1+3=8, 4+6+2+5=17, 2+1+2=5) = 5$（经 $v_1$）
  • $d(t_1, t_3) = \min(4+6+2=12, 2+1+2=5) = 5$（经 $v_1 \to v_3$）
  • $d(t_2, t_3) = \min(3+1+2=6, 5+2=7, 3+1+6+4=14) = 6$（经 $v_1 \to v_3$）

步骤 2 — $G_D$ 的 MST： 边 $(t_1, t_2)$ 代价 5 + 边 $(t_1, t_3)$ 代价 5 = 总代价 10。两条边构成 MST。

步骤 3 — 展开：

  • $(t_1, t_2)$ 展开为路径 $t_1 \to v_1 \to t_2$
  • $(t_1, t_3)$ 展开为路径 $t_1 \to v_1 \to v_3 \to t_3$

合并得子图：$\{t_1, v_1, t_2, v_3, t_3\}$。

步骤 4 — 最终解的代价： $2+3+1+2=8$（$v_1$ 和 $v_3$ 为 Steiner 节点）

原最优解也是 8，KMB 在此例中达到最优。

7.2.4 近似比分析

KMB 算法在最坏情况下的近似比不超过 $2\left(1 - \frac{1}{k}\right)$，其中 $k$ 为终端节点数。实践中通常在 5% 以内接近最优解。

八、快速重路由与保护算法

8.1 IP FRR — 无环备选路径（LFA）

8.1.1 LFA 条件的推导

问题：邻居 $N$ 是源 $S$ 到目的地 $D$ 的可行备选下一跳吗？

若 $N$ 将数据包发回给 $S$ 再发给 $D$，就形成短暂环路（微环，micro-loop）。为避免此情况，$N$ 到 $D$ 的”自然”路径（不经过故障的 $S \to N$ 链路或 $S$ 本身）必须小于 $N \to S \to D$ 的距离。

LFA 不等式：

推导：如果不等式成立，意味着 $N$ 的转发决策（走自己的最短路径去 $D$）不会经过 $S$。因为若 $N$ 的最短路径经过 $S$，则 $Distance(N, D) = Distance(N, S) + Distance(S, D)$，不等式不成立。因此不等式保证无环。

8.1.2 数值计算示例

  • 从 S 到 D1：直接代价 10
  • 从 N 到 S: 5；从 N 到 D1: 3；从 N 到 D2: 2

检查 N 是否为 S→D1 的 LFA：

成立！N 到 D1 的最短路径是直接的去往 D1（3），而不是经 S 再到 D1（5+10=15）。所以 N 是 S→D1 的有效 LFA。

检查 N 是否为 S→D2 的 LFA：

（注意 S→D2 的最短路径是 S→N→D2 = 5+2 = 7）
成立。N 是 S→D2 的有效 LFA。

反例 — LFA 不存在：

  • $Distance(N, D) = 10$（N 到 D 的最短路径，直接边）
  • $Distance(N, S) + Distance(S, D) = 1 + 3 = 4$
  • $10 < 4$？否！

不成立！N 不是 LFA。因为 N 到 D 的最短路径（直接边代价 10）比经过 S 再到 D（1+3=4）更长。但在链路 S—N 故障的情形下，S—N 不可用，若 S 仍试图通过 N 转发去 D，N 收到后会查自己的路由表，发现自己的最短路径竟然是通过 S 到 D…但 S—N 已经断了。实际上此时 N 的最短路径会变成直接去 D 的 10（因为 S—N 故障被检测到），但由于收敛延迟存在微环危险。

这正是 remote LFA 发挥作用的地方：S 通过隧道把数据包发送到既满足 LFA 条件又能到达 D 的远程节点。

8.1.3 P 空间与 Q 空间

  • P 空间：从故障点（或保护节点）出发，不经保护链路的可达节点集
  • Q 空间：能不经过保护链路到达目的地 D 的节点集
  • PQ 节点：P 空间与 Q 空间的交集——可同时被 S 隧道到达且能无环转发至 D 的节点

8.2 MPLS FRR 的保护路径计算

8.2.1 链路保护（NHOP）

主 LSP：$R1 \to R2 \to R3 \to R4$

保护链路 R2—R3。R2（PLR，Point of Local Repair）预先建立绕过 R2—R3 的备份 LSP，NHOP 为 R3。

通常使用 RSVP-TE 信令在故障发生前预先建立备份 LSP（1:1 或 facility 保护）。

保护切换过程：

  1. R2 检测到 R2—R3 链路故障（BFD 通常在 30-50ms 内检测到，三层心跳间隔 10ms × 3）
  2. R2 在转发表中将主 NHLFE（Next Hop Label Forwarding Entry）替换为备份 NHLFE
  3. 流量切换到备份 LSP

总切换时间： 故障检测（~30ms）+ 转发表更新（<5ms）+ 传播延迟 ≈ < 50ms。

8.2.2 节点保护（NNHOP）

主 LSP：$R1 \to R2 \to R3 \to R4$

保护 R3 节点。备份 LSP 需绕过 R3（即从 R2 不经 R3 到达 R4），NNHOP 为 R4。

节点保护比链路保护更严格：备份路径不能经过被保护节点（即使有不同接口）。这要求拓扑中存在完全不经过 R3 的 R2→R4 路径。

9.1.3 增量 SPF (iSPF)

当拓扑变化仅影响少数 LSA 时，无需重新计算整棵 SPF 树。iSPF 只重新计算受影响的节点子树。

适用条件：

  • 仅叶节点（leaf node）的链路变化 → 几乎无需重新计算
  • 中间节点的链路代价变化 → 仅重算其子树
  • 新节点加入 → 在现有 SPF 树上嫁接
  • 节点/链路删除 → 剪枝并重算替代路径

典型收益：iSPF 将计算时间减少 80-95%（实际网络中存在大量只影响叶节点的瞬态 LSA 更新）。

9.2 IS-IS 的 SPF 与部分路由计算 (PRC)

IS-IS 将路由信息分为两类：

  • 邻接关系（LSP 中的 neighbor TLV）：影响拓扑 → 需全 SPF 计算
  • IP 前缀（LSP 中的 IP Reachability TLV）：不影响拓扑，仅是叶子附着信息 → 仅需 PRC（Partial Route Calculation）

PRC 比重：在典型 ISP 网络中，90%+ 的更新为 IP 前缀变化（路由注入/撤销），仅 10% 涉及实际拓扑变化。PRC 的计算量远小于全 SPF。

十一、流量工程与约束路由

11.1 CSPF（Constrained Shortest Path First）

标准 Dijkstra 只基于单一度量（链路代价）选择最短路径，无法满足 TE LSP 的带宽、亲和性等约束。CSPF 扩展 Dijkstra，在松弛操作前增加约束检查。

CSPF 剪枝规则（在 Dijkstra 松弛前应用）：

  1. 带宽约束：$reservable_bw(link) < LSP_bw_req \Rightarrow$ 排除该边
  2. 管理组（Affinity）约束：$link_color \not\subseteq LSP_affinity \Rightarrow$ 排除
  3. 跳数限制：$hop_count > max_hops \Rightarrow$ 停止沿此路径继续
  4. SRLG 不相交流：若已被其他成员 LSP 使用且要求 SRLG 不相交 $\Rightarrow$ 排除该边及共享同一 SRLG 的边

示例：

链路信息：L1(可用 4G), L2(可用 2G), L3(可用 8G), L4(可用 5G)。LSP 请求 3Gbps。

  • Dijkstra：L2（最短，代价 1）
  • CSPF：L2 被排除（2G < 3G），选择 L1（代价 2，可用 4G）
